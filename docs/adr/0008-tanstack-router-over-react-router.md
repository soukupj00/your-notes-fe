# 0008 — TanStack Router over React Router

- Status: Accepted
- Date: 2026-07-25

## Context

Through M3 the app was effectively a single view (`App.tsx` renders `NotesHome`); no client router existed.
M4 introduces multiple destinations - Archive, Trash, Settings (with a labels subsection), tag-filtered feeds, and potentially per-note deep links - and an advanced-search surface whose state (free-text query, sort mode, active tag filters, lifecycle scope) should be shareable, refresh-proof, and back-button navigable.
That pushes search/filter/lifecycle state into the URL.
The project prioritises quality, robustness, and long-term maintainability over development cost, and is already on Zod v4 for validation.

## Decision

Adopt **TanStack Router** (file-based routing, route tree generated by its Vite plugin) as the client router, rather than React Router.
Routes: `/`, `/archive`, `/trash`, `/settings` (+ `/settings/labels`), `/tag/:id`, and optionally `/note/:id`.
Search/filter/sort/lifecycle state lives in **typed, validated search params**: each route's `validateSearch` consumes the Zod schema directly (no adapter needed, since the project is on Zod v4), and `retainSearchParams` middleware preserves relevant params across navigation.

## Considered options

- **React Router** — mature, ubiquitous, lower contributor barrier for an open-source project.
  Rejected as the primary because its search-param story is stringly-typed (`useSearchParams` → `URLSearchParams`), requiring hand-rolled parsing and validation everywhere search/filter state is read - which is exactly the surface M4 leans on most.
- **No router / a view-state context** (like the existing `ViewModeProvider`) — simplest, but forgoes URL addressability, deep-linking, and browser back/forward, and strains as views multiply.

## Consequences

- Search, tag-filter, sort, and lifecycle scope become type-safe URL state - shareable and restorable - which is the backbone of the M4 advanced-search work.
- Adds a build-time route-tree generation step (the Vite plugin) and a newer, smaller ecosystem than React Router; contributors must learn TanStack's conventions.
- End-to-end type safety on routes and params catches mistakes at compile time across a growing view set.
- Trade-off accepted: more upfront ceremony and a less ubiquitous library, in exchange for typed URL-state ergonomics that compound across every M4 feature.
