# M4 Slice 2.5 - Sidebar nav shell

**Status:** planned - design agreed, nothing implemented.

**Goal:** Replace the hand-rolled nav shell with the vendored shadcn `Sidebar`: icon-collapsible on desktop and tablet, a `Sheet` drawer on mobile, with a sticky header.

**Depends on:** Slice 2 (the search box and its controls live in the Navbar, which this restructures).

**Blocks / feeds:** Slice 3 Task 4 (semantics, tab order, skip-to-content link) should land *after* this, on the single-`<main>` shell. Slice 3 Task 1 (colour tokens, de-purple) owns any sidebar tinting, which this slice deliberately does not do.

**Design decisions:** [ADR 0010](../../adr/0010-shadcn-sidebar-as-nav-shell.md). Read it first - it records why each vendored-file edit exists, and those edits look like accidents without it.

**Cross-cutting rule:** new strings ship `en` + `cs`. Land with tests.

## Context

`pnpm dlx shadcn@latest add sidebar` has already been run.
It created `src/components/ui/sidebar.tsx`, `src/components/ui/sheet.tsx`, `src/hooks/use-mobile.tsx`, and appended sidebar colour tokens to `src/styles/globals.css`.
None of it is wired into the app yet, and the appended CSS is HSL in an otherwise all-OKLCH file.

Today `src/components/layout.tsx` renders a full-width `Navbar`, then a flex row of a `hidden ... sm:block` `<aside>` and a `<main>`, with the mobile drawer as a `Dialog` restyled with `top-0 left-0 h-full rounded-none`.
`SideNav.tsx` renders hand-rolled `<Link>` elements for the five `NAV_ITEMS` plus every tag.

### Task 4 - Shell restructure

### Task 5 - Sidebar content

- [ ] Give each of the five `NAV_ITEMS` buttons a `tooltip` - the 48px rail is unusable without them.
- [ ] Put the tag list in a `SidebarGroup` **hidden when collapsed**. Tag pills keep their current expanded treatment (dot + name); they never degrade to bare dots.
- [ ] Replace the `onNavigate` prop with `useSidebar()`'s `setOpenMobile(false)` internally, so the drawer closes itself and callers stop having to know about it.
- [ ] `navItems.ts` is untouched and stays the single source of destinations.

### Task 7 - Scrolled shadow

- [ ] Pure CSS, in `globals.css`, inside `@supports (animation-timeline: scroll())`: a keyframe animating `box-shadow` with `animation-timeline: scroll()` and `animation-range: 0 48px`, so the shadow grows over the first ~48px and notes read as sliding under the bar.
- [ ] Add `motion-reduce:transition-none` / a `prefers-reduced-motion` guard where this introduces motion. Do **not** attempt the full `reducedMotion` preference here; it is declared in `PreferencesProvider` but unimplemented, and that is separate work.
- [ ] Firefox has `animation-timeline` in preview only. It gets the sticky header and `border-b` with no shadow, and that is accepted (ADR 0010). No JS fallback.
