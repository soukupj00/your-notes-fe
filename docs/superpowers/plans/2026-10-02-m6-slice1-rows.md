# M6 slice 1: Rows - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Note, Tag, NoteTag and Attachment row is built by one factory in one module, with one id minter and one timestamp stamp, and a Tag update is atomic like a Note update already is.

**Architecture:** `src/lib/new-note.ts` becomes `src/lib/rows.ts`, the one place that mints ids (`crypto.randomUUID`) and stamps timestamps; it gains `newTag`, `newNoteTag`, `newAttachment` and `cloneAttachment` beside `newNote`.
The three action hooks and the Conflicted Copy build their rows through it, so the `uuid` package goes.
The Local Store gains `tags.update(id, change)`, mirroring `notes.update`, so `updateTag` stops being a get-then-put.
`models.ts` owns the runtime lists behind `NoteState`, `ReminderRepeat` and `AttachmentKind`; the copies in `reminder.ts` and `backup.ts` import them, and one test pins the vendored contract's enums to them.
Behaviour-preserving throughout, with one harmless change: a Conflicted Copy's attachment clones get fresh timestamps, which nothing reads.

**Tech Stack:**
- React 19, TypeScript 6;
- Dexie 4 behind the `LocalStore` seam (ADR 0020), with an in-memory implementation under the same contract suite;
- Zod 4 (the vendored contract in `src/contract/index.ts`, the backup manifest);
- Vitest with Testing Library and `fake-indexeddb`;
- Biome; pnpm, Node 24.

**Spec:** `PLAN.md` milestone M6, slice 1, and [ADR 0022](../../adr/0022-interfaces-and-closures-not-classes.md).
Evidence: [the refactor survey](./2026-10-02-refactor-survey.md), section A ("Action hooks") and section D ("Row construction", "Two id minters", "Loose primitives").

## Review Focus

1. Two writers updating the same Tag in the same tick (a rename and a recolour) must both land; `updateTag` used to read-then-put and could lose one (contract case in Task 3).
2. A Conflicted Copy whose attachment bytes are not on this Device and whose fetch fails must still get a clone row with the metadata, never throw and never leave the Note without its copy (test in Task 4).
3. A second conflict must reuse the "Conflicts" Tag found by name, not mint a second one (test in Task 4).
4. A draft's id supplied to `newNote` must be kept, because the address bar already names it (ADR 0014; test kept in Task 1).
5. `updateTag` with a whitespace-only name must keep the old name rather than blank it (hook test in Task 3).

```ts
import type { Attachment, AttachmentKind, Note, NoteTag, Tag } from '@/models.ts';

// The store stamps nothing (src/data/CLAUDE.md): every id and timestamp a row is born with
// comes from here. A secure context is already required (ADR 0018), so randomUUID is safe.
export const mintId = () => crypto.randomUUID();
export const nowIso = () => new Date().toISOString();

/**
 * The one place that knows a Note's defaults. An id may be supplied because it enters the URL when
 * the editor opens (ADR 0014); `trashedAt` passes through for the purge sweep to key off.
 */
export function newNote(data: Partial<Note>, now = nowIso()): Note {
  return {
    id: data.id ?? mintId(),
    header: data.header ?? '',
    description: data.description ?? '',
    body: data.body ?? '',
    state: data.state ?? 'active',
    pinnedAt: data.pinnedAt,
    color: data.color,
    trashedAt: data.trashedAt,
    remindAt: data.remindAt,
    repeat: data.repeat,
    createdAt: now,
    updatedAt: now,
  };
}

export function newTag(name: string, color?: string, now = nowIso()): Tag {
  return { id: mintId(), name, color, createdAt: now, updatedAt: now };
}

export function newNoteTag(noteId: string, tagId: string, now = nowIso()): NoteTag {
  return { noteId, tagId, createdAt: now, updatedAt: now };
}

export type NewAttachmentOptions = {
  thumbnail?: Blob;
  duration?: number;
  width?: number;
  height?: number;
};

/** `file` is already validated (`lib/attachments.ts`); a File is a Blob and is stored as is (ADR 0007). */
export function newAttachment(
  noteId: string,
  file: File,
  kind: AttachmentKind,
  options: NewAttachmentOptions = {},
  now = nowIso()
): Attachment {
  return {
    id: mintId(),
    noteId,
    kind,
    mime: file.type,
    blob: file,
    thumbnail: options.thumbnail,
    // The thumbnail's own blob id on the server, so it syncs ahead of the full bytes.
    thumbnailId: options.thumbnail ? mintId() : undefined,
    duration: options.duration,
    width: options.width,
    height: options.height,
    name: file.name,
    size: file.size,
    createdAt: now,
    updatedAt: now,
  };
}

/**
 * A new row under `noteId` with the source's metadata and bytes. Every row has one owner and bytes
 * are write-once by id (ADR 0017), so a copy is a new id; a source without bytes yields a clone
 * that waits for them the same way.
 */
export function cloneAttachment(source: Attachment, noteId: string, now = nowIso()): Attachment {
  return {
    ...source,
    id: mintId(),
    noteId,
    blob: source.blob?.slice(0, source.blob.size, source.blob.type),
    createdAt: now,
    updatedAt: now,
  };
}
```

```ts
async function conflictsTagId(store: LocalStore, now: string): Promise<string> {
  const found = await store.tags.findByName(CONFLICTS_TAG_NAME);

/**
 * Keeps this Device's losing version as a Conflicted Copy (CONTEXT.md), tagged "Conflicts".
 * Attachments are cloned under new ids so each keeps one owner (ADR 0017); bytes not downloaded
 * here are fetched first, as nobody else could upload them under the new id. Returns the Tag's id.
 */
export async function keepConflictedCopy(
  store: LocalStore,
  local: Note,
  deviceName: string,
  at = new Date(),
  fetchBytes: (id: string) => Promise<Blob | undefined> = async () => undefined
): Promise<string> {
  const now = at.toISOString();
  const id = mintId();

  const clones: { from: string; clone: Attachment }[] = [];
  for (const from of extractAttachmentIds(local.body)) {
    const row = await store.attachments.get(from);
    if (!row) continue;
    // ponytail: bytes the server does not have either are lost to the copy; it keeps the metadata.
    const blob = row.blob ?? (await fetchBytes(from).catch(() => undefined));
    clones.push({ from, clone: cloneAttachment(blob ? { ...row, blob } : row, id, now) });
  }
  let body = local.body;
  for (const { from, clone } of clones) {
    body = body?.replaceAll(`data-attachment-id="${from}"`, `data-attachment-id="${clone.id}"`);
  }

  await store.notes.add(
    newNote({ ...local, id, header: conflictedHeader(local.header, deviceName, at), body }, now)
  );
  for (const { clone } of clones) await store.attachments.add(clone);

  const tagIds = (await store.tags.listLinks())
    .filter((l) => l.noteId === local.id)
    .map((l) => l.tagId);
  const conflicts = await conflictsTagId(store, now);
  for (const tagId of new Set([...tagIds, conflicts])) {
    await store.tags.link(newNoteTag(id, tagId, now));
  }
  return conflicts;
}
```
